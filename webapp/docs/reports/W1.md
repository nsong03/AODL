## 4. Deviations from the work order, and why

1. **`sphere_loop` is 300 µs, not 400 µs.** With the specified geometry (radius 6 µm centred
   at `(0, 0, 6)`, start at the south pole, θ 0→π, φ = 3θ, `closed=True`) the loop spends the
   whole move at mean `Z ≈ 6 µm`, so `∫Z dt = 2.39e-9 m·s > 2.06e-9` and `plan_motion` picks
   Shepard at 400 µs whatever the closure (`+1.02 MHz` margin). 300 µs is plain Eq. S19 at
   87 % of the Eq. 1 budget (`+1.28 MHz`); 350 µs already fails. The alternative —
   `f_z_bias="auto"` at 400 µs — would have made a "defaults otherwise" example non-default.
2. **`eta ≠ ½` under `shepard="auto"`** is implemented in `planner.build_plan` (Eq. S19 first,
   then `aodl.waveform.shepard.auto_config(..., eta)` with the lateral spans/headroom
   `synthesize` itself would compute) because `plan_motion`'s `"auto"` has no `eta` knob; a
   note records the chosen spacings. At `eta = ½` `plan_motion(shepard="auto")` is used
   verbatim.
3. **`py.typed` markers** were added to `src/aodl` and `src/aodl_webapp` (not in the owned
   list). Both packages are editable-installed through `.pth` path entries, so `mypy
   webapp/backend/src/aodl_webapp` run from the repo root resolved `aodl` as an *installed,
   untyped* package and failed on every import. The backend `pyproject.toml` also sets
   `mypy_path = "../../src"` for runs from `webapp/backend`.
4. **`webapp/ruff.toml`** (extends the root config, declares `aodl`/`aodl_webapp`/`aodl_advanced`
   first-party) so `webapp/scripts` sorts imports like the backend; the backend `pyproject.toml`
   carries the same `known-first-party`. Without it ruff treats `aodl` as third-party under
   `webapp/backend` (its nearest config) and demands a different import order than the root.
5. **`packages.find`** with `include = ["aodl_webapp*", "aodl_advanced*"]` instead of the
   literal `packages = ["aodl_webapp", "aodl_advanced"]` — setuptools needs the sub-package
   `aodl_webapp.routes` listed too; `find` is the robust spelling of the same intent.
6. **Backend tests import `conftest` as a top-level module** (`from conftest import …`), not
   relatively: `webapp/backend/tests` deliberately has no `__init__.py` because W2 shares the
   directory.
7. **`TypeError` wording** for a bad move stays `"must be a Lift, Translate or Hold (or a
   Path)"` so the root `tests/test_spec.py` regex keeps matching.
8. **Codegen under `phases="random"` + auto-Shepard** emits the B ladders' `phase0` arrays
   explicitly (with a comment) instead of `rng=…`: `plan_motion(shepard="auto")` draws the
   Eq. S19 attempt's phases first, an explicit `ShepardConfig` only the ladders', so a seeded
   `rng` alone cannot reproduce the Studio plan. Eq. S19 (and `shepard="always"`) random
   plans emit `phases="random", rng=np.random.default_rng(seed)` as specified.
9. **`/api/frame` honours the same `movie_mixing_order` rule as `/api/simulate`** (fallback to
   order 1 above 160 groups unless pinned), so the exact frame and the movie show the same
   spot set; the plan/report always use the requested order.
10. **The fixture generator** additionally stores `example_id` and `plan_mode` in each
    `<id>.json`; `examples.json` is the whole `/api/presets` response (W3's loader accepts both
    shapes).

## 5. What the frontend / W2 / W4 must know beyond API.md

- **Four spots at a hand-over centre** (two coincident main-trap spots + two shadows); add
  coincident spots in intensity. `n_terms == 1` for all four. On the plateau: one spot.
- **`fade_events[0]` of `single_lift_hold` is `(0.0 µs, "y")`**, and x hand-overs appear
  **twice** at the same instant (`153.6, 153.6`): `aodl.api.fade_schedule` takes the union of
  the rungs' `|g| = g_centre` crossings, and the two rungs' roots differ at the 1e-16 level so
  `np.unique` keeps both. Dedupe events within ~1 ns in the UI (badge/timetable).
- **The 4×4 example falls back to mixing order 1** (165 groups at `t = 2τ` > 160); pass
  `movie_mixing_order=3` to opt in (4.4 s / 80 frames). The flagship has 462 groups at order 3.
- **IM3 ghosts are below the `1e-3` power cut at `drive_strength = 0.3`** (~1e-4 of a trap):
  the movie of a 3×3 at order 3 shows 9 spots, `/api/frame`'s uncut `spots` show all 49 and
  the exact image contains the ghosts. Order 3 matters for the exact frame and the per-trap
  powers, not for the spot *list*.
- `plan.notes` = `aodl`'s report notes followed by the web layer's (`t_pad_us = 0`, `amp ≠ 1`
  under Shepard, `eta ≠ ½` auto); `simulate.notes` = fallback/override, dark-start and clamp
  notes.
- The flagship simulate payload is 1.7 MB at 80 frames (400 spots/frame mid-hand-over); W3's
  48-frame rule for > 36 traps keeps it near 1 MB. 4×4: 270 kB.
- `GET /` serves `frontend/dist` with an SPA fallback when it exists (it does now: W3 built
  it); `AODL_STUDIO_FRONTEND_DIST` overrides the location.
- `make lint-backend` runs `mypy src/aodl_webapp src/aodl_advanced` from `webapp/backend`;
  W2's package imports cleanly today (`mypy webapp/backend/src/aodl_webapp` from the root
  includes `routes/advanced.py` and passes).
- `Makefile` sets `AODL_STUDIO_STRICT_ADVANCED=1` for every target except `dev*`/`serve`
  (which force `0` so the basic app runs while the advanced package is being worked on).
- Root `mypy src/aodl` has 10 pre-existing numpy-2.5 stub errors (`ndarray.max(initial=…)`
  overloads) in files I do not own; the repo's `ci.yml` presumably pins an older numpy.
