## 3. Measured numbers (summary; details in VERIFICATION.md)

* Static tweezer at `3τ`: Gaussian approximation vs `intensity_frame` — max relative pixel
  difference **4.6e-15**, peak ratio 1.000000; unit check `peak·wx·wy·π/2/power = 1.000000`.
* 24-point circle `Path` (R = 10 µm, 300 µs, `s19`): simulated spot at `t + τ/2` vs the
  requested law **1.0e-14 µm** over the middle 80 %; 0.019 µm from the ideal circle (spline
  interpolation, not tracking); band widths 0.9709 MHz on all four channels = lateral span /
  (2 λF/v) on each axis.
* `trajectory_efficiency`: static tweezer product **0.522006 = η_peak⁴** everywhere; flagship
  min **0.3875** at t = 383 µs (Bx 0.705, By 0.761); 3 dB bandwidth 27.90 MHz; first-AOD usable
  12.05 MHz.
* `code_python` of all seven examples runs under `python -I` (rc 0; 1.5–30 s each).
* e2e (a): brightest pixel approximation vs exact at `70 + τ/2`: **0.000 w0** apart (same
  192-px grid pixel), planes 5.000 / 5.000 µm, exact/approx peak 0.987.
* e2e (b): aperture envelope 0, `f_inst` 1.4e-14 MHz, fill mask exact, carrier `V(u)` ≤ 2.9e-11
  relative — at `t = 70 + τ/2` and at `0.6 τ`.
* e2e (c): single_lift_hold at the first **x** hand-over + τ/2 (`159.369 µs`): four spots — two
  coincident main spots (groups 0 and 2) and shadows at **±123.600 µm** with **P/P_main =
  0.5004** each; badge "2 shadow tweezers off canvas at ±123.6 µm (x fade)". Main / `power_ref`
  = 2.43 (see O2).
* Playback: 4×4 **52–56 fps** (three runs; worst gap 33–50 ms, 64 spots/frame); flagship **35–38 fps** with 400
  spots at the cursor.
* Flagship in the browser: `/api/plan` 185 ms / 152 kB, `/api/simulate` 1.83 s / 1.0 MB (48
  frames, order-1 fallback noted), movie ready 2.7 s after navigation, 0 console errors.
* Production path: uvicorn serves the bundle at `/`, deep link `/basic?example=pick_and_place`
  survives a hard reload, assets served as files, unknown `/api/*` → 404.

## 5. Open issues (not fixed) and recommendations

| # | issue | recommendation |
|---|---|---|
| O1 | `python -m mypy src/aodl` fails locally on Python 3.13 + numpy 2.5.3 + mypy 2.4.1 (10 `call-overload` errors on argument-less `ndarray.min()/.max()` in `api.py`, `check/metrics.py`, `check/report.py`, `viz/movie.py`, `waveform/shepard.py`); CI on 3.11 is unaffected. | Spell the ten calls as `np.min(x)` / `np.max(x)`, or pin `numpy<2.5` in the `dev` extra until the stubs settle. Files untouched by this work, so left to the core owner. |
| O2 | `power_ref` (API.md §5.1) is the **median** spot power over all frames. For a drive that spends most of its time inside fades (`single_lift_hold`: 124 µs fades every 247 µs on each axis) the median is a quarter-power rung pair, so the UI's "P/P_ref" reads 2.43 for the main trap at a hand-over, 1.22 for each shadow and ≈ 4.9 on the plateau — numbers that depend on the example rather than on the physics. | Define `power_ref` as the plateau power — the maximum over frames of the frame-summed power of coincident spots (what the frontend's `peakNormalization` already computes for brightness) — or add it as a second field. Additive API change; both sides in one commit. **Resolved by the closer:** `power_ref` is now the median over lit frames of the brightest spatially-merged trap (`simulation.reference_power`), so a trap reads 1.0 on its plateau and through a hand-over and the shadows read 0.5; API.md §5.1 updated; `test_power_ref_is_the_plateau_trap_power` pins it. |
| O3 | `aodl.api.fade_schedule` lists one hand-over twice when the two rungs' `|g| = g_centre` roots differ at the 1e-16 level (the frontend dedupes within 1 ns; the generated code's comment block prints both). | Dedupe in the core with a tolerance (e.g. `np.unique(np.round(t / 1e-12))` or a 1 ns merge) so every consumer sees one event per hand-over. Core file, not touched here. |
| O4 | `make serve` does not depend on `make build`; without a bundle `/` answers with a JSON pointer rather than the UI. | Either `serve: build` in the Makefile (adds ~5 s of `tsc` + `vite build` to every `make serve`) or keep the README note. **Resolved by the closer:** `serve: build` in the Makefile. |
| O5 | The CI fixture-freshness step (`gen_frontend_fixtures.py` + `git diff --exit-code`) assumes regeneration is byte-identical across numpy versions. It is here (numpy 2.5.3 reproduces the committed files exactly); a future numpy that changes `repr` of a float at the last digit would turn the step into a false alarm. | If that happens, regenerate the fixtures in the same change, or compare with a tolerance script instead of `git diff`. |
| O6 | Headless playback dropped single frames (worst gap 50–67 ms) on both the 4×4 and the flagship while averaging well above 30 fps; the flagship draws 400 spots per frame on the main thread. | Acceptable for v1. If the flagship ever needs 60 fps, render the XY canvas in a worker or skip the isometric view above ~200 spots. |
| O7 | The movie's `movie_mixing_order` is not exposed in the UI (always `null`, so the 4×4 and 10×10 always fall back to order 1 and say so in a note). | A toggle in the Options panel wired to `movie_mixing_order=3` (4.4 s / 80 frames for the 4×4 per W1) — a v1.1 item. |
